# v2.8.0 音频合成引擎 SPEC（待确认）

> 目标：让 Collinx **真的发出声音**，且引擎与产品解耦——后续可单独替换/优化引擎而不动业务代码。
> 状态：**待 Gate 确认**，确认后进入实现。

---

## 0. 为什么要做

v2.7.0 复核发现的产品级缺口：`useTransport` 注释明确「本实现不引入 AudioContext」——Collinx 只能编辑与导出 MIDI，**不产生任何声音**。一个"音乐工程平台"不能出声，用户无法判断自己写的东西对不对，AI 的建议也无从试听。这优先于任何 UI 打磨。

## 1. 现有资产盘点（调研结论）

| 资产 | 状态 | 复用方式 |
|---|---|---|
| `packages/audio`（C++/JUCE） | 无 package.json、未构建、不在 JS 构建链；`BuiltinSynth` 只有 SineWaveVoice；面向 VST3 Host 桌面端 | **借鉴**其 `SynthesiserVoice` + ADSR + voice 池 + preset 格式设计；不做代码复用 |
| Tone.js 15 | 成熟但 ~400KB，Transport 用 AudioContext 时钟，与现有 Web MIDI 的 `performance.now()` 时钟域冲突 | 不引入 |
| Web Audio API | 浏览器原生、零依赖、时钟精确 | **实现基础** |

## 2. 目标 / 非目标

**目标**
1. 播放键真的出声；钢琴卷、乐谱、编曲区的试听按钮出声
2. 引擎独立包，UI 只依赖**接口**不依赖实现
3. 音色可扩展：新增音色不改引擎代码
4. 时钟域清晰：引擎内部用 `AudioContext.currentTime`，与现有 `performance.now()` 严格隔离
5. 可离线渲染（导出音频）——复用同一套合成逻辑

**非目标（本期不做）**
- 采样播放（SoundFont/SF2）——体积与授权复杂度，另开
- VST3/CLAP 插件宿主——需要原生链路，另开
- 复音均衡/母带处理/音频效果链（混响/压缩）——M2 再议
- 替换 C++ 引擎或做 Electron 版

## 3. 包结构（工程解耦的关键）

```
packages/audio-engine/                 ← 独立包，零运行时依赖
  src/
    index.ts                           ← 对外唯一入口（只导出接口与工厂）
    engine/
      types.ts                         ← AudioEngine 接口 + VoiceEvent（引擎的唯一契约）
      engine.ts                        ← 引擎实现：voice 池 / 调度 / 生命周期
    voice/
      voice.ts                         ← 单声部（对应 JUCE SynthesiserVoice）
      adsr.ts                          ← 包络（Attack/Decay/Sustain/Release）
      unison.ts                        ← 复音与声部分配
    instrument/
      instrument.ts                    ← 音色定义（数据驱动）
      instruments.ts                   ← 预置音色表
    core/
      context.ts                       ← AudioContext 生命周期（user gesture 解锁）
      clock.ts                         ← 时钟换算（performance.now ↔ audioTime）
      noise.ts                         ← 噪声缓冲（鼓组用）
    render/
      offline.ts                       ← OfflineAudioContext 离线渲染（导出音频）
```

**依赖方向（单向，不可逆）**：
```
ui  ──依赖──▶  @collinx/audio-engine ──依赖──▶ Web Audio API（浏览器）
                       ▲
                       │ 接口相同
              （未来的 @collinx/audio-native / Electron 实现可替换）
```
- `audio-engine` **不依赖** core / ui / agent 任何包 → 引擎可单独发版、单独测试
- ui 通过 `AudioEngine` 接口 + 一个 `createEngine()` 工厂拿实现
- 想换引擎 = 换工厂实现，**业务代码零改动**

## 4. 核心接口（契约先定，实现后写）

```ts
export interface AudioEngine {
  readonly ready: boolean;
  unlock(): Promise<void>;                  // 用户手势后调用，解锁 AudioContext
  noteOn(note: VoiceEvent): void;           // 立即发声
  noteOff(noteId: string): void;
  schedule(events: VoiceEvent[], atSec: number): void;  // 精确调度（AudioContext 时钟）
  setMasterVolume(v: number): void;
  setInstrument(instrumentId: string): void;  // 换音色（数据驱动，不改引擎）
  dispose(): void;
  getStats(): EngineStats;                   // 活动声部 / CPU 估算 / 采样率
}
```

`VoiceEvent`：`{ id, midi, velocity, durationSec?, instrumentId?, pan? }`

## 5. 音色库（M1 范围，5 个）

数据驱动，每个音色 = 一组参数（不写代码）：

| id | 名称 | 合成方式 |
|---|---|---|
| `piano` | 钢琴 | 3 振荡器（含轻微失谐）+ 低通 + 快 ADSR + 击弦噪声 |
| `epiano` | 电钢 | 2 振荡器（正弦+三角）+ 温和低通 + 中 ADSR |
| `strings` | 弦乐 | 锯齿+低通（缓慢开合）+ 慢起音 + 合唱失谐 |
| `bass` | 贝斯 | 正弦+方波混合 + 低通 + 快释放 |
| `drum` | 鼓组 | 噪声（打击）+ 音高下滑正弦（底鼓） |

后续新增音色 = 往 `instruments.ts` 加一条数据，不动引擎代码 ✓（这是"可扩展"的验收标准）

## 6. 与现有系统的集成点

| 位置 | 改动 |
|---|---|
| `useTransport` | 播放时把工程音符转成 `VoiceEvent[]` 交给引擎；**MIDI 输出保持并行不变**（外接设备仍可用） |
| 新增 `AudioProvider` | ui 内 React Context，持有引擎实例；设置页加"音频引擎：WebAudio / 静音" |
| 钢琴卷 / 乐谱 | 试听按钮走同一个引擎（此前是死按钮或无行为） |
| 导出 | 复用 `render/offline.ts` 做 OfflineAudioContext 渲染 → 导出 WAV |

**时钟域策略（最容易出错的地方）**：
- 引擎内部一律 `AudioContext.currentTime` 调度，**不用** `performance.now()`
- 跨域换算集中在 `core/clock.ts`，唯一转换点，带注释说明两个时钟域不可混用（现有代码已有同类警告）

| 里程碑 | 内容 | 验收 |
|---|---|---|

## 8. 验收方式

- **单测**：ADSR 包络时序、voice 分配与回收、音色表完整性、时钟换算
- **集成测试**：App 内触发播放 → 断言引擎收到正确的 VoiceEvent 序列（不依赖真实发声）
- **真实发声**：自动化脚本用 `OfflineAudioContext` 渲染一段，断言输出**非静音**（能量 > 阈值）——这是"真的出声"的客观判据，不靠人耳
- **性能**：32 声部同时发声，CPU 与内存不失控
- **回归**：ui 全量测试保持绿

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 浏览器自动播放策略拦截 | `unlock()` 挂在首次用户手势；未解锁时 UI 显式提示"点击启用声音" |
| 用户已有外接设备（MIDI） | 引擎与 MIDI 输出**并行**，设置页可切"仅外设 / 仅内置 / 两者" |
| 引擎与 UI 耦合 | 接口先定；ui 只依赖 `AudioEngine` 类型，禁止 import 引擎内部路径（用 lint 规则或代码评审把关） |
| 未来换原生引擎 | 接口保持不变，C++/N-API 版实现同一 `AudioEngine`，ui 不动 |

## 10. 已决策（2026-10-16 用户拍板）

| 问题 | 决策 |
|---|---|
| 音色方案 | **混合：采样 + 合成**。鼓组/贝斯/电钢用合成；钢琴/弦乐走采样 |
| 内置 vs 外接 MIDI | **默认只走内置引擎**，外接设备在设置里手动开（避免双响与困惑） |
| 本轮范围 | **引擎 + UI 接入一起做** |

### 10.1 采样的现实约束（必须知会）

我无法凭空提供版权清晰的乐器采样素材。因此采样层实现为：

- 引擎支持 `soundfont` 类型的音色（SF2 加载器），**音色库文件由部署方/用户放置**（设置里可选路径与 URL）
- **未加载采样时自动回退到同名合成音色**（钢琴→合成钢琴、弦乐→合成弦乐）→ 零依赖也能出声，不阻塞
- 授权提示：SF2 需选用 CC0/CC-BY 许可的音色库（如 GeneralUser GS、MuseScore 附带库），部署文档中注明

这样"混合"是**架构上成立**（instrument 类型可扩展），素材到位即生效，不需要改引擎代码。
