## 二、本轮修复

| # | 债务 | 证据 | 修复 | 验证 |
|---|---|---|---|---|
| 1 | **自动保存完全不读设置** | provider 写死 `AUTOSAVE_INTERVAL_MS`；设置页标签「分钟」而 value 是 1..30 被当秒；默认 300 不在选项里 → 下拉空白 | `autosavePolicy()` 统一**秒**为单位（默认 300s，下限 10s）；provider 读 `general.autoSave`，关掉即不排期；选项值改 60..1800 | 5 条策略测试 + 2 条组件测试（选项值/写回） |
| 2 | **撤销步数设置不生效** | `MAX_UNDO = 50` 硬编码；设置页 100/500/1000/不限制全无效 | `state.undoLimit` + `SET_UNDO_LIMIT`；`resolveUndoLimit()` 解析（`unlimited`=硬上限 1000）；provider 跟随设置裁剪 | reducer 上限/裁剪 + provider 初始值（设置 50 时栈确实 50） |
| 3 | **导出采样率不读设置** | `renderNotesToWav` 固定 44100 | WAV 与分轨导出传 `settings.audio.sampleRate` | tsc + e2e（默认值路径不变） |
| 4 | **导出器偷看 TempoMap 私有字段** | `midi-exporter.ts` 两处 `as unknown as { tempoChanges }` | TempoMap 增加 `getTempoChanges/getMeterChanges/getKeyChanges` | core 单测 + tsc |
| 5 | 架构书数字漂移 | core「51 测试」→48、ui「74+21 spec(90)」→89+22(99)、工具「18」→19、日期、desktop/audio-engine 规模 | 全部按实测更新 | 文档审查 |

**行为变更（需要知道）**

- 撤销上限默认值从 50 变为 **1000**（因为设置默认是 `unlimited`）。快照是整工程 JSON，1000 步会更吃内存；UI 文案已写明「最多 1000 步」。
- 自动保存仍是 5 分钟一行（默认 300s），只是现在**可改/可关**。

## 三、仍不生效的设置（登记，不造假装可用）

| 设置组 | 叶子 | 为什么不本轮做 |
|---|---|---|
| `audio.audioDevice.*` | input / output | 需要 `setSinkId`（浏览器支持不均）+ 输入设备通路（当前无录音输入） |
| `audio.bufferSize` / `audio.latency` | 2 | 只能映射到 `AudioContext.latencyHint` 的粗档位，且创建后不可改；要做就必须定义"重启音频上下文"交互 |

| `midi.agent.autoSuggest` / `explanationLevel` / `confirmationMode` | 3 | 需要进 prompt 与审批策略（涉及 AI 行为，应单独迭代 + 评估） |
