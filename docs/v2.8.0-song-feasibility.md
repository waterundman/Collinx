# Collinx "能否做出一首歌" 可行性分析（v2.8.0）

> 2026-10-19｜方法：真实点击 + 拦截发给 LLM 的请求 + Hook AudioContext
> 对照基准：Ableton Live / Logic Pro / Bitwig Studio / FL Studio 的「做一首歌」链路

---

## 一、先修掉的端到端断链（三轮 TDD 的成果这轮才真正生效）

新增的 `transport.setTempo` / `mixer.setTrackVolume` / `project.stats`
单测全绿，但真实点击时 AI 仍回答「我没有这个工具」。**两层根因**：

| 层 | 根因 | 修法 |
|---|---|---|
| 1 | `AGENT_SYSTEM_PROMPT` **硬编码了工具清单**（"能生成动机、和声进行…"），随注册表变化而过期 → 与 tools schema 成为**双真相源** | 改为「本次提供的 tools 就是你的全部能力，不要依据预先记忆的清单」 |
| 2 | **dev server 从未真正重启**。`pkill -f "vite --port 5181"` 在 Git Bash 下对 Windows node 无效，日志里其实是 `Port 5181 is already in use`，旧进程用着旧的预打包 `@collinx/agent` | `netstat -ano \| grep :5181` 取 PID → `taskkill //PID <pid> //F` |

**修复后实测**（拦截 DeepSeek 请求）：

```
发给 LLM 的工具数: 14 → 17
含 project_stats: true | transport_set_tempo: true
```

- 问「工程里有多少音符」→ 「当前工程共有 **21 个音符，3 条轨道，3 个小节，速度 120 BPM**
  （这是只读统计，没有改动工程，也没有生成提案）」
- 说「把速度改成 88 BPM」→ 「已生成 1 条待审批提案：从第 1 小节起改为 88 BPM」，
  并主动提示「若只想让某一段变慢，把起始小节改成对应位置」

## 二、成熟 DAW 的「做一首歌」链路 vs Collinx

一个 DAW 的骨架是 **audible feedback loop**：听到 → 判断好不好 → 调整。逐环节对照：

| # | 环节 | Ableton / Logic / Bitwig / FL 的通行做法 | Collinx 现状 | 判定 |
|---|---|---|---|---|
| 1 | 曲式结构 | Session/Arrangement + Marker/Section | Section（INTRO/VERSE/CHORUS…）+ 编排器 + 曲式模板 | ✅ |
| 2 | 写旋律 | Piano Roll、MIDI 录制、量化 | Piano Roll + 实时 MIDI 录制（v2.2.0）+ 量化 | ✅ |
| 3 | 和声 | Chord Track（Logic）/ 和弦 MIDI | AI 建议和声 + 生成动机 | ✅ |
| 4 | 配器（多轨） | 无限轨道、任意乐器、任意音区 | **固定 3 轨**（旋律/贝斯/和弦） | ⚠️ |
| 5 | 音色 | 内置音源 + VST/AU/CLAP | **无法选音色**（引擎有 VST3 宿主，UI 未接） | ❌ |
| 6 | 混音 | 推子 + 实时电平表 + FX 链 | 推子（自绘 div）+ FX 建议，**无电平表** | ⚠️ |
| 7 | 母带 | Master 总线 + 处理链 | 有 Master 轨，无处理 | ⚠️ |
| 8 | **试听** | 按下即响 | **无声**（见下） | ❌ **根本缺口** |
| 9 | 导出 | WAV / MP3 / MIDI / 乐谱 | MIDI / MusicXML / PDF（无音频） | ⚠️ |

### 环节 8 的实测证据

在页面加载前 Hook `AudioContext`，然后按播放键：

```
AudioContext 创建次数: 0
resume() 调用次数:     0
振荡器创建次数:        0
播放头:                m1.3 → m2.3   （在走）
```

**Collinx 目前是「会走时间的无声播放器」。**

根因不是 bug，是 v2.0.0 的**设计选择**：`useTransport` 明确"本实现不引入
AudioContext"，全程依赖 Web MIDI 把音符发给**外部音源**。没有 MIDI 设备时，
用户写下的音符完全没有声音。

## 三、结论：能做「乐谱级草稿」，做不出「能听的成品」

| 能力 | 结论 |
|---|---|
| 画出一首歌（音符 + 结构 + 和声 + 乐谱 + MIDI） | ✅ **完整可用** |
| 听到一首歌 | ❌ **完全无声** |
| 拿到能听的成品（音频文件） | ❌ 只有 MIDI/PDF |
| 做出有层次的编曲（多轨/多音色） | ❌ 固定 3 轨、无音色选择 |

**对用户的实际影响**：能"看见"作品，无法"听见"作品。听不到就无法判断旋律好不好，
AI 生成的动机也只能靠读音符想象 —— 创作闭环在**最关键的一环断裂**。

## 四、优化路线（按对"做出一首歌"的影响排序）

| P | 事项 | 现状 | 理由 |
|---|---|---|---|
| **P0** | **浏览器内出声** | `audio-preview.ts` 已交付，**待接入 transport** | 没有声音就没有创作闭环，这是 DAW 的第一性 |
| **P0** | 音频导出（WAV） | 无 | 成品必须是能播的音频 |
| **P1** | 音色选择（接 VST3 宿主） | 引擎已就绪，UI 未接 | 决定"像不像一首歌" |
| **P1** | 轨道可增（不限 3 条） | 固定 3 轨 | 配器层次 |
| **P1** | Mixer 电平表 | 无 | 混音没有判断依据 |
| **P2** | Graph 改工程结构图 | 无边散点图 | 见 v2.8.0-acceptance.md |
| **P2** | Teaching 空状态入口 | 整页依赖已应用方案 | 闭环 |

### P0 的已交付部分

`packages/ui/src/services/audio-preview.ts`：

- Web Audio 双振荡器（锯齿 + 方波，失谐 4 cents）+ 指数包络
- `midiToFrequency`（A4=440）/ `velocityToGain`（平方曲线，接近人耳感知）
- **失败即静音**：AudioContext 不可用或未获用户手势时静默降级，不打断播放
- 6 条单测覆盖频率映射、八度关系、力度曲线、NaN/越界钳制

**接入点**（下一步）：`useMidiOutput` 的 `send()` 是 MIDI 事件的唯一出口
（`encodeNoteOn` / `encodeNoteOff`），在那里并行送一份给 `AudioPreview`
即可实现"有 MIDI 设备走设备、没有走内置合成器"的双通路。

**注意**：不要改编 transport 的时钟 —— 时间轴已由 v2.0.0~v2.3.0 的 lookahead
调度器验证过，改动会牵动拍号/loop/count-in/录制一整片已验收行为。
