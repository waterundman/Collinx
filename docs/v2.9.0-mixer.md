# v2.9.0 混音闭环（Mixer Truth）

> 2026-10-24 ｜ 代码 `eb53980` → 本轮 ｜ 执行方式：**主 session 全量自证**（未派子代理、无独立验证者）

## 一、解决了什么

v2.8.0 把「推子」从装饰变成真实接线，但同一类断线还剩 6 处：界面能改、数据能存、声音不变。
本轮把 6 处全部接通，并让导出与播放共用同一条混音链。

| # | 断线 | 现在 |
|---|---|---|
| 1 | 静音 M | fader = 0（真静音） |
| 2 | 独奏 S | 并集语义；mute 优先；master 不参与 |
| 3 | 声像 pan | `StereoPannerNode`，等功率 |
| 4 | FX 链（6 类） | `fx-chain.ts`，播放与导出共用 |
| 5 | 导出丢混音 | `renderNotesToWav(notes, { mixer })` |
| 6 | 删轨 | `REMOVE_MIXER_TRACK`（级联 + undo）+ UI × 按钮 |
| + | AI 看不见混音 | 新只读工具 `mixer.inspect`（工具总数 17 → 18） |

## 五、过程中抓到的 3 个真 bug（都是"看起来绿"的）

1. **FX 链重建未断直通支路** → 干湿两路并联。单测（节点计数）全绿；数值验收发现 4kHz **+6.02dB**、100Hz 该衰减却 **+2.68dB**。修：`rebuild` 先 `input.disconnect()`；并补一条"唯一出口不是 output"的断言。
2. **静音用 `setTargetAtTime(0)`** 指数逼近永远不为 0 → 导出漏出 −52dBFS。修：静音走 `setValueAtTime(0)`；导出侧 `instantParams` 写静态终值，−6dB 不再被过渡尾巴污染。
3. **`isFinite` 判 dB**（v2.8.0 遗留同类风险）→ 本轮统一收口到 `parseGainDb`，`-Infinity` 显式保留。

## 八、e2e 现状（3 例失败均为既有问题）

用临时配置复用 5181 dev server 跑了 mixer / mixer-persistence / mixer-rollback / full-flow：

| 结果 | 说明 |
|---|---|
| 14 passed | 含 `mixer.spec` 全 7 例（M/S 切换、加轨、布局） |
| 3 failed | 全部**与本轮无关**，已用 HEAD 工作树对照证明 |

- `mixer-rollback.spec`：断言「2 条 demo 提案 + 1 条混音提案 = 3」。demo 预置提案在 v2.4.0 已移除，spec 自 v1.13 未更新。
- `full-flow.spec`（2 例）：断言 `piano-roll-canvas` 可见。实测 `height: 0`；**HEAD 副本（`eb53980` 工作树）在同一视口下同为 0** → 既有布局问题，不是本轮引入。
- 结论：e2e 套件需要单独一轮「按当前 UI 重写」，不在本轮范围。
