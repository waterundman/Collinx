# v3.0.0 UI 基线 SPEC

> 状态：已确认（画布 = Ardot 设计画布；范围 = 全站 10 页；本文件为唯一裁决依据）
> 设计画布：`Collinx UI Baseline`（fileId 740318843064293）
> 上游事实：`packages/ui/src/styles/design-tokens.css` 为本轮唯一令牌源

## 0. 口径

- **画布 = Ardot 设计画布**，是全站视觉基线，不是代码渲染层。现有 4 处 `<canvas>`（PianoRoll / GraphView / TasteTimelineView / ArrangerPanel）只作为设计还原对象。
- 本轮**只做设计与落点清单**，不提交代码。
- 冲突裁决顺序：本 SPEC > 通用 UI 规范 > 个人审美。

## 2. 方向一：建立设计画布

### 2.1 作用范围

| 层 | 内容 | 数量 |
|---|---|---|
| P 页面 | compose / arrange / orchestrate / mixer / score / taste / teaching / agent / graph / settings | 10 |
| C 组件 | TabPill、TransportBar、通道条、面板头、按钮、输入、空状态、Toast | 8 组 |
| S 状态 | 空工程 / 播放中 / AI 流式 / 冲突告警 / 错误态 | 5 |

### 2.2 初始化方式

1. 令牌映射：`design-tokens.css` → Ardot 变量集 `Tokens`，Light / Dark 双 mode。
2. 基准画框：`1440×900`（主）、`1280×800`（窄）、`1920×1080`（宽）。
3. 栅格：8pt 步进；DAW 密集区用 12 列，表单/设置区用 4 列，不混用。

### 2.3 集成方式

- 命名：`P/视图/状态` · `C/组件/变体` · `S/视图/场景`（前缀是批量改稿的检索锚点）。
- 页面只允许放**组件实例**，禁止页面内手绘重复元素；改组件即全站生效。
- 每页附「变更标注」块，条目号对应 §3 表格，画布与文档可对账。

## 4. 方向三：「朴素」操作哲学

| 原则 | 判据（可审计） |
|---|---|
| 层级靠间距与字重 | 禁止新增大面积阴影/渐变/玻璃；同屏强调色 ≤1 |
| 动效只表达因果 | 仅 `opacity`/`transform`，120–200ms，`--ease-standard`；禁弹跳、禁缩放入场、禁自动播放 |
| 一屏一主任务 | 每视图仅一个主操作按钮，次操作降为文字按钮 |
| 单击即生效 | 除破坏性操作外不二次确认；不弹成功 toast |
| 渐进披露 | 默认只显高频控件，高级参数进抽屉/命令面板 |
| 键盘优先 | 主流程全键盘可达，`⌘K` 兜底 |
| 状态克制 | 同屏常驻提示 ≤1；loading 用行内骨架，不用全屏遮罩 |
| 空态不卖萌 | 一句话 + 一个动作，无插画、无长引导 |

**审计口径**：每阶段统计新增阴影/渐变数、动画条数、同屏按钮数、toast 数、全屏遮罩数，超阈值打回。

## 5. 约束（不做）

- 不改业务逻辑，不动 core / agent / audio 包。
- 不引入动画库（需单独立项）。
- 不做响应式重排，仅三档画框适配。
- 不为死组件做设计。
- 不做大爆炸改版，逐阶段验收。

### 8.1 实施中发现的两处偏差
1. **画布页签文案与 i18n 不一致**：画布原写「配器 / 谱面 / 品味」，实际 `zh-CN.json` 是「编制 / 乐谱 / 口味档案」——已按产品文案改正画布，设计稿不再自造 copy。
2. **dark.css 与 tokens 的 border 值本就不同**：运行时生效的是 dark.css（#2a2a36 / #3a3a48），tokens 里那份从未生效。已归一到 tokens 值（#212327 / #363a3f），全站分隔线略深一档，无功能影响；若嫌偏暗，改 tokens 一处即可。
