# v3.3.0 记谱排布层重构（落地回执）

> 触发：用户反馈「继续重构乐谱显示，这部分问题很大，连音识别等，音符的区间放置都是错误的」。
> 本轮只动**谱面排布**（时间 → 符号），不动数据模型、不改交互契约。

## 一句话结论

谱面排布从「按音符逐个查表猜 VexFlow 时值字符串」变成「纯函数记谱引擎 `notation.ts`：时值 → 保 tick 的符号序列 → 按拍点/小节切分 → 分声部 → 补休止 → 几何相邻才连音」。三类系统性错位的**根因**都在这一层被切掉，而不是逐个打补丁。

## 根因与修法

| # | 用户可见现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 时值对不上：`0.1 / 0.3 / 0.4` 全变 16 分，`0.75 / 1.5 / 3` 全变四分 | `durQnToVfDuration` 是「查表 + 兜底最近值」，查不到就退到 16 分/四分 | `decomposeDuration()`：按 `NOTATABLE_VALUES` 贪心最大优先分解，**tick 严格守恒**（`0.1 → 32`、`1.5 → q.`、`3 → h.`），差值低于 `GRID=1/16` 才丢弃 |
| 2 | 附点音符看起来是附点，后面音符却整体前移 | 附点只加视觉修饰符（`Dot.buildAndAttach`），`getTicks()` 没变 | 附点必须走构造参数 `dots: n`（改 tick），**同时** `Dot.buildAndAttach(..., { all: true })` 让和弦每个键位都带点 |
| 3 | 跨小节的长音画成一个「越界音符」，没有连音线 | 完全没有切分逻辑，音符按原始时值塞进起拍所在小节 | `planNoteSpans()` 三段切：①跨小节 → 先切到小节末 ②小节内不在拍点上 → 切到下一个拍点 ③仍超长 → `decomposeDuration` 分解 |
| 4 | 连音线连错（同音高但中间有休止也连） | 若以「音高相同」为判据就会误连 | `spansAreContiguous()`：**只认几何相邻**（同小节 `a.end == b.start`；跨小节 `a` 到小节末且 `b.offset == 0`），音高不参与判断 |
| 5 | 同拍不同时值被串行排开，整小节宽度翻倍 | 一条 `Voice` 串行 `addTickables`，第二个音被推到第 5 拍 | `assignVoices()` 贪婪装箱（**不设声部上限、绝不截短时值**）+ `joinVoices().format()` 纵向对齐；>2 声部只 `console.warn` 不改数据 |
| 6 | 小节内没被休止填满，第二声部整体被挤到左边 | `Voice` tick 不足时 `Formatter` 按实际 tick 总量摊开 | `fillVoiceRests()` 按拍点切休止，保证「音符 tick + 休止 tick == 小节长度」 |
| 7 | 长音跨小节后被塞回第 1 小节（第二段画在小节首） | `engravingPlan` 把 `spans` 全塞进**来源小节**的桶 | 按 `span.bar` 各自归桶 |
| 8 | 4 小节以上的音挤成一团、音符越过小节线 | 纸面谱 8 小节/行 → 每小节 108px，小于 VexFlow 最小间距 | `PAPER_BARS_PER_SYSTEM = 4`（≈220px/小节）+ 纸面宽量测 + `planScorePages` 同步 `barsPerSystem` |
| 9 | 低音谱表的整小节休止符飘在五线谱上方 | 休止符锚点音高写死 `b/4`（高音谱表内，低音谱表外上方） | `REST_KEY_BY_CLEF`：treble `b/4` / bass `d/3` / alto·tenor `c/4` / percussion `b/4` |
| 10 | 空小节的整小节休止符贴着小节线 | `Formatter` 把唯一 tickable 摆在可用区起点 | `rest.setCenterAlignment(true)`（Formatter 在 justify 后补偿 `centerXShift`） |
| 11 | `四分 → 八分 → 八分 → 四分` 的两个八分音符各自挂符尾，连不到梁 | `Beam.generateBeams` 按 `groups`（4/4 半小节）分桶后，**桶内出现四分及更长的音就整桶作废** | `beamRuns()`：先切成「短于四分且首尾相接」的片段，再逐段 `generateBeams`；`二分 → 八分 → 八分` 才侥幸能连，正是本条的证据 |

## 已知限制（本轮未修，需改 VexFlow 内部）

**和弦内相邻三度（全音符/二分音符）不做符头水平避让。** VexFlow 5 的 `StaveNote.buildNoteHeads()` 只在 `|lineDiff| < 1`（同度/二度）时置 `displaced`，三度不位移；而全音符符头宽 ≈1.3 个间，三度间隔（1 个间）必然叠成「8」字形。示例工程低音谱表的 `E3–G#3–B3` 全音符和弦即为此例。修它需要覆写内部 `buildNoteHeads` 并同步放大 `notePx`（否则间距分配不足、与相邻音符碰撞），超出「排布层重构」的范围，列为后续项。

## 一个反例：为什么「四小节/行」不是审美偏好

旧值 8 小节/行的纸面宽是 920px → 每小节 108.75px。VexFlow 对「4 个音 + 1 个休止 + 1 个临时记号」的最小排版宽度约 130px，`Formatter` 在放不下时会**把音符推出小节线**（不是压缩字号、也不是报错）。所以「音符越过小节线」这一条用户可见缺陷，与「每行小节数」是同一个问题 —— 只改 `Formatter` 的宽度参数无效。
