## 二、AI 功能审查（核心缺口）

**当前 AI 100% 是假的**：

| 证据 | 位置 |
|---|---|
| 唯一的 agent handler 对任何输入返回固定串 `[compose] Rule-based response for "<prompt>": suggested progression C-Am-F-G` | `ProjectProvider.tsx:476-490` |
| 全仓零 LLM 调用（无 fetch/openai/anthropic/deepseek/sdk/.env） | 全仓 grep |
| 设置层无 model/apiKey/provider 字段 | `types/settings.ts:64-68` |
| 初次进入 Agent 面板即有 2 条**预置假提案**，actor 硬编码标 `gpt-4o` / `claude-3` | `ProjectProvider.tsx:275-309` |
| 聊天不产生 `DiffEnvelope`、不写 `pendingDiffs` → 与工程图无数据依赖 | `AgentChat.tsx` 仅 `recordToolCall` |

实测（真实浏览器）：

```
prompt="帮我生成一个 C 大调的动机"      → "[compose] Rule-based response for "帮我生成一个 C 大调的动机": suggested progression C-Am-F-G"
prompt="这个和声进行为什么好听"          → 同上（仅 prompt 回显不同）
prompt="assemble a string quartet arrangement" → 同上
```

**AI ↔ 工程图断点**：`ProjectProvider.tsx:485` —— 响应在此定格为字符串，无「文本 → ops → ADD_PENDING_DIFFS → DiffEngine → graph」桥接。

**未接入的既有能力**（7 个孤儿工具，已实现但无 UI 路径调用）：`composer.generateMotif`、`composer.suggestHarmony`、`planner.planTask`、`engraving.reflowLayout`、`teaching.explainOrchestration`、`taste.analyzeExport`、`taste.rankWithTaste`。

**DeepSeek 实测结论**（`sk-53bc…8915`）：密钥有效；OpenAI 兼容；`/models` 可作连通性测试；支持 `tools`（function calling，`finish_reason=tool_calls`）与 `stream`（SSE）。→ 接入方案技术可行。

## 五、真实 API 验证（DeepSeek）

用提供的密钥对 `POST https://api.deepseek.com/chat/completions` 与 `GET /models` 实测：密钥有效、支持 `tools` 与 `stream`。
端到端冒烟（真实浏览器 + 真实密钥）：AI 回复为有结论/理由/替代方案的音乐解释（非硬编码），并如实报告工具未产出提案 —— 正是该报告驱动了缺陷 N2 的发现与修复。
