# v3.1.0 三条能力接线

> 前置结论来自 v3.0.0 审查：三块都是「缺数据源」，不是「缺 UI」。
> 因此本轮全部先补源、再接界面，**没有任何一条靠造数据过关**。

## 1. 插件宿主

**补的源**：主进程真实文件系统扫描。

| 层 | 文件 | 做了什么 |
|---|---|---|
| 主进程 | `desktop/src/plugin-scanner.ts` | 扫 `.vst3` / `.clap`，跨目录去重，id 由路径哈希生成（跨次扫描稳定）；目录不存在返回空数组，不当错误 |
| 主进程 | `desktop/src/main.ts` | `plugins:scan` → 真实扫描；`plugins:load` → 恒返回 `ok:false` + 「原生宿主未接线」 |
| 桥 | `desktop/src/preload.ts` | 暴露 `plugins.*` 领域方法（不暴露 ipcRenderer） |
| 渲染 | `ui/src/services/desktop-bridge.ts` | `plugins` 命名空间**可选**：旧壳缺失按不可用处理 |
| 渲染 | `ui/src/services/plugin-host.ts` | 无宿主 → `unavailable`；宿主报错 → 原样透传原因；**永不返回伪造条目** |
| 界面 | `Settings/PluginSettings.tsx` | 设置 →「插件」：自定义扫描目录、扫描、列表、真实失败原因 |

**边界（明确没做）**：DSP 加载。需要原生插件宿主进程 + `plugins:load` 真实实现；当前按钮只给原因。

**红线测试**：浏览器无宿主时必须 0 条插件；宿主返回 `ok:false` 时必须原样报错，不得补默认值。

## 3. MIDI 效果链

**补的源**：发送前的事件流（而非工程数据）。

| 层 | 文件 | 做了什么 |
|---|---|---|
| 服务 | `ui/src/services/midi-effects.ts` | `transpose`（±24 半音）/ `velocity`（×0.1–2）；纯函数、越界钳制、`normalizeMidiEffects` 丢弃非法项 |
| 调度 | `ui/src/services/midi-schedule.ts` | `buildPlaybackEvents(..., midiEffects?)` 在编译事件前作用于**音符副本** |
| 走带 | `ui/src/hooks/useTransport.ts` | `midiEffects` 走 ref，播放中改效果不破坏 `play()` 引用 |
| 设置 | `Settings/MidiSettings.tsx` | 设置 → MIDI → 效果：增删、启用、数值编辑 |
| 测试 | `services/__tests__/midi-effects.test.ts` | +9 条：纯函数不改入参 / 链式顺序 / 双向钳制 / 禁用跳过 / 非法项清理 / 调度器音高真的变化且 on-off 成对、时间不变 |

**定位说明**：效果作用在发送前，**不修改工程音符**，因此存 `settings.midi.effects`（会话设置）而不是工程图。关闭即恢复原声。
