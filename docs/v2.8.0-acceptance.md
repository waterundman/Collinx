## 二、AI 落地与规则严密性

### 规则严密性：高（本次最大的正面发现）

让 AI 做它做不到的事，第 3 轮实测原文：

> 「现在工程里一共有多少个音符 —— **同样无法查询，没有音符统计类工具**」
> 「我可以用 `composer_generateMotif` 生成…（**但注意：它生成的是音符，不会改工程速度**）」
> 「`arranger_expandSection` 可以按目标能量展开乐段，**同样不涉及 BPM 字段**」
> 「如果 Collinx 面板里有速度轨和工程统计视图，**那两处是改 BPM 和数音符最直接的地方**」

**没有幻觉、没有编造工具、明确说出能力边界并给替代路径。**
在"自然语言驱动工程"这类产品里，这是少见且关键的品质。

### 落地是真的

- 真实 LLM（首次 2s 返回，回复含「E4 起拍 · 八分音符 C5-G4 上行 · 落在主音 C」）
- 提案 `PROPOSAL_ONLY → applied`，时间线有 `composer.generateMotif` 完整参数
- **应用后音符 `21 → 36` 真实落盘**，二次应用按钮消失（幂等）

### 但工具集有缺口（比规则问题更实际）

| 用户想做的事 | 有无工具 | 表现 |
|---|---|---|
| 改 BPM | ❌ **无** | 只能建议"去面板手动改" |
| 查工程统计 | ❌ **无** | 明确说"无法查询" |
| 生成动机 | ✅ | 正常 |
| 展开乐段 | ✅ | 正常 |

→ **最高频的参数修改反而没有工具**。这不是规则不严密，是**工具面覆盖不全**。

## 三、Graph：功能定位不清（第二轮深测）

### 已修复的真 bug

v2.6.0 写了「按音高分档着色 + 显示 C4」，但**从未生效**：

- 音符字段是 `pitchMidi`（`core/src/io/midi-exporter.ts:104`）
- GraphView 读的是 `data.pitch` → `NaN` → `Number.isFinite` 为 false
- 结果：着色回退默认灰、文案回退 `node.type`

修复后实测对比：

| | 修复前 | 修复后 |
|---|---|---|
| 标签 | 21 个全是 `NoteSpan` | `E3 / G#3 / B3 / D3 / E4 / F#4 / A4…` |
| 颜色 | 全同灰 | 低音粉 → 高音青，按音高分档 |

**这类「字段名错 + 静默回退兜底值」的失效最难发现**：不报错、控制台无警告，
只在视觉上退化成"看起来没做"。

### 修复后仍在的设计问题（「功能不明确」的根源）

| 问题 | 证据 |
|---|---|
| **没有一条边** | `graph.addNode("NoteSpan", …)` 只加节点，音符图全仓无 `addEdge` |
| **力导向退化成斥力散开** | 无弹簧力 → 节点被推到画布边缘排成环形 |
| **canvas 渲染 → DOM/无障碍不可见** | `circleCount: 0`、`textCount: 0`，屏幕阅读器读不到任何节点 |
| **不表达音乐结构** | 音符的 bar/beat 完全没体现，看不出小节、拍、声部关系 |

**根本判断**：把 21 个音符各做成**孤立节点**，本质是**把乐谱画成散点图**。
图的表达力来自"关系"，而音符之间本就没有图意义上的边——**这个视图无论怎么修
都不会有信息量**，除非改设计：

- **方案 A（推荐）**：不做"音符图"，改**工程结构图**——`Section → Track → Phrase → Note`
  的层次，边表示隶属。这与「可审计的工程图」定位一致。
- **方案 B**：若要音符粒度，按 `bar × pitch` 二维排布（等价 piano roll），不用力导向。

**当前的问题不是"画得不好"，是"这个视图没有回答任何用户问题"。**
