## 一、能否完整做出一首歌

| 环节 | 结果 | 证据 |
|---|---|---|
| 加音符 | ✅ | 双击钢琴卷帘，`21 音符 → 22` |
| 改 BPM | ✅ | `#transport-bpm` 120 → 96 |
| 加乐段 | ✅ | 点「引子 · 4 小节」后编排页出现 `Intro / 引子` |
| 生成编排 | ⚠️ 有按钮未验证结果 | 「生成编排」+ 曲式模板 `Pop ABABCB` |
| 混音调音量 | ❌ **轨道推子不是标准控件** | 轨道推子是自绘 div + `onMouseDown`（`mixer-fader-*`，MixerConsole.tsx:275）；`input[type=range]` 只出现在 FX 参数旋钮上 → 推子无键盘操作、无 `role="slider"` |
| 导出 MIDI | ✅ | `project.mid` 251 bytes |
| autosave 持久化 | ✅ | 刷新后仍 `22 音符` |

**结论**：**能做出"一段音乐"并导出 MIDI，但还不等于"一首歌"**。缺三样：

1. **只有 MIDI 导出，没有音频导出**（用户拿不到能听的成品）
2. **混音推子不可键盘操作**（`0` 个 range input），鼠标拖自绘元素既不精确也无无障碍
3. **轨道固定 3 条**（旋律/贝斯/和弦），无法新增乐器类型或轨道数

## 二、AI 是否落地实盘、规则是否严密

### 正面（都实测到了）

| 项 | 证据 |
|---|---|
| 真实 LLM | 2 秒返回，回复是真实音乐学描述：「E4 起拍 · 大小调内自然音 · 八分音符 C5-G4 上行 · 落在主音 C」 |
| 提案结构化 | 右侧历史记录：`Composer / PROPOSAL_ONLY / applied`，标签 `旋律` |
| 工具调用可审计 | 时间线 `composer.generateMotif`（成功）+ 完整 motif JSON（name/tags/nodes） |
| **真的落盘** | 应用后 `21 音符 → 36 音符`（+15，与 AI 声称的 16 个音符吻合） |
| 幂等 | 二次应用按钮消失，音符保持 36 |

**这一层是项目最扎实的部分**：AI 产出不是聊天里的漂亮话，而是带 revision 的 diff 并真写进 ProjectGraph。

### 问题

| 问题 | 证据 | 严重度 |
|---|---|---|
| 「HarmonyBot 在线」无依据 | 静态文案，与真实健康检查无关联 | 🟠 |
| 提案未显示 baseRevision | 用户看不到"这条提案基于哪个版本" | 🟠 |
| 无撤销入口 | 已应用提案只在历史记录里显示 `applied`，无法一键回滚 | 🔴 |
| `agent.chat` 状态不收敛 | 应用完成后工具时间线仍显示「运行中」 | 🟠 |

## 三、UI 结构严密性（对照成熟 DAW）

成熟 DAW（Ableton / Bitwig / Logic）在同类界面上有共同底线：**关系可视化、实时电平反馈、控件可键盘操作、同一位置不承载多种语义**。逐条对照：

| # | 问题 | 证据 | 严重度 | 对照基准 |
|---|---|---|---|---|
| 1 | **Graph 只有节点没有连线** | 21 个 `NoteSpan` 孤立环形排列、全同名、无端口/无工具栏 | 🔴 | Bitwig The Grid：节点必须有端口与连线 |
| 2 | **Mixer 推子是自绘 div** | 轨道推子 = div + onMouseDown（无 `role="slider"`、无键盘）；仅 FX 参数用 range | 🔴 | 所有 DAW 推子可键盘微调 |
| 3 | **推子位置与数值矛盾** | 滑块在 +6 区，标签显示 `0.0 dB` | 🔴 | — |
| 4 | **Mixer 无电平表** | 无实时电平，无法判断削波 | 🟠 | 每轨 meter + Master 响度 |
| 5 | **header-status 语义漂移** | compose=`21 音符` / arrange=`编排器` / mixer=`3 轨道` / agent=`0 条待审` | 🟠 | 同一位置应只承载一种语义，或带标签 |
| 6 | **Teaching 无法自主触发** | 自动文案「暂无关联的编曲方案」，页内无生成入口 | 🟠 | 空状态应提供完成路径 |
| 7 | **加乐段入口不明确** | 靠「引子·4小节」这类段落起点按钮，无「添加乐段」明示 | 🟠 | — |
| 8 | **Taste 左栏近乎空白** | 版本时间线仅 1 个点，占 ~400px | 🟡 | — |
| 9 | Mixer 推子高度失控 | 推子占满整屏高度，比例失衡 | 🟡 | — |

### 四处未闭环

1. **Teaching**：依赖"已应用的方案"，但页面内没有生成入口 → 用户卡在空状态
2. **Graph**：展示了节点却不展示关系 → 图的价值（关系）完全丢失
3. **Mixer**：有推子但无电平 → 用户不知道是否削波，混音失去判断依据
4. **AI 提案**：有"已应用"但无"撤销" → 与项目"可审计可回滚"的定位不符

## 优先级建议

| P | 问题 | 理由 |
|---|---|---|
| **P0** | 音频导出（WAV/MP3） | "做出一首歌"的终点是能听的成品，现在只有 MIDI |
| **P0** | AI 提案撤销 | 与"提案需审批、可回滚"的核心定位冲突 |
| **P1** | Graph 画连线 + 端口 | 图不画关系等于没做 |
| **P1** | Mixer 推子改 `input[type=range]` + 加电平表 | 可用性与无障碍双问题 |
| **P1** | header-status 单一语义 | 跨 tab 认知成本 |
| **P2** | Teaching 空状态给入口 | 闭环 |
| **P2** | 加乐段显式入口 | 发现性 |
