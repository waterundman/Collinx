# v3.2.0 曲谱界面 / 编曲逻辑重构（落地回执）

> 依据：`docs/v3.0.0-ui-spec.md`（朴素操作哲学）、本版 SPEC v3.2.0（S1→S2→S3）。
> 用户已确认的三个方向：**纸面优先**曲谱、**结构 + 和弦都升级**的编曲、**真实性与微动效优先**的全局交互；**不使用 AI 生图**。

## 一句话结论

曲谱从「一张铺满深色背景的 VexFlow 画布」变成「居中纸张对象 + 可缩放 / 可翻页 / 可点击定位的谱面」；编曲从「只能看的色块条」变成「可拖动 / 改长度 / 键盘微调 / 复制 / 删除的 graph-native 结构编辑」；和弦轨从「固定 7 项循环」变成「直接选根音 + 性质」；全局把三处「界面承诺了但做不到」的交互（⌘1–9、⌘S、页签语义）补成真的。

## 顺带修掉的实测缺陷

1. **紧凑谱只占面板左侧 1/3**：谱表宽度是 `max(540, bars×110)`，4 小节在 1000px 面板里固定 540px。改为紧凑态量测可用宽并取 `max(最低宽, 可用宽)`；全尺寸纸面仍固定 920px（纸不随窗口变宽）。
2. **拖动换算基准错**：`barWidth` 取的是 root 宽度（含 padding、且 `.barContainer` 有 `min-width: 520`），拖 1 小节会跳 2 小节。改用被拖块的定位父级宽度。
3. **单击选中失效的风险**：`pointerdown` 上无条件 `preventDefault()` 会让浏览器不再派发 `click`。改为只在「改长度」模式吞默认行为。
4. **拖动后的 click 抑制标记会吃掉下一次点击**：改为自清除标记（`setTimeout(0)`），拖动结束的那一次 click 仍被吞。
5. **起点卡片建乐段有 off-by-one**：`startBar` 直接取 `endBar` 最大值（空图为 0）、`endBar = startBar + bars`，首个乐段落在「第 0–4 小节」。改为 1-based 且长度为 `bars`。
6. **编排页下半屏纯黑死区**：`.sectionMargin` 只是带下边距的 block，里面的 `flex: 1` 无处可长。改为 flex 列并让空态吃掉剩余高度居中；无乐段时不再画空的小节标尺。
7. **生成按钮的 135° 渐变**：违反 SPEC「禁大面积渐变」，改纯色填充。
8. **`ArrangementView` 角色标签硬编码中文**：en 界面显示「主歌 / 副歌」。改为 `t("arranger.formRoles.*")`（经用户裁定，同步更新 v118-stage0 的 4 条语言相关断言）。

## 已知遗留

- 编排区在**没有乐段**时是一整屏居中的空态卡片（信息正确，但页面上半部分仍显得空）；有乐段后会填满。
- 紧凑谱 4 小节在超宽面板里单小节可达 260px（谱面类应用惯例，未设上限）。
- `ArrangementView` 的 `title` 悬浮提示仍是原生的，与检查器信息重复（未做统一浮层）。
- S3 未覆盖：设置页各分区的键盘可达性、`AgentChat` 打字点的 reduced-motion 例外（全局兜底已压到瞬时）。
