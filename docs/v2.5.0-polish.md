## 二、配色系统修复（对比度归零）

| 主题 | 修复前 | 修复后 |
|---|---|---|
| light | 295 处违规 / 78 唯一组合 | **0 / 0** |
| dark | 142 处违规 / 51 唯一组合 | **0 / 0** |

根因与修复：

| # | 根因 | 后果 | 修复 |
|---|---|---|---|
| 1 | `light.css` 未覆盖 dark 的 xAI 别名 token（`--ink` 等） | `--ink: #fff` 用在白底上 → 顶栏 "Collinx" **完全不可见**（1.0:1） | 补齐 light 的全部语义 token |
| 2 | `--text-muted`(#66666e) / `--text-disabled`(#44444e) 过暗 | 暗色下顶栏状态、空态提示、时间线文字 ≈ 2.1:1 | 提亮到 5.9:1 / 3.7:1，并把误用 `--text-disabled` 表示「状态」的地方改回 `--text-muted` |
| 3 | 强调色背景 + `--text-primary` 文字（13 个文件） | 白字压亮青/绿底 1.45–1.86:1 | 引入 `--text-on-accent`，脚本批量修正 13 个 CSS Module |
| 4 | 浅色主题强调色过亮 | 白字压青底 4.1:1、链接对白底 1.9:1 | light 强调色整体加深（#0284c7→#0369a1 等），链接改用 `--accent-primary` |
| 5 | 未声明 `color-scheme` | 暗色主题下原生 `<select>` 仍是白底浅字 | `:root{dark}` / `[data-theme=light]{light}` |
| 6 | VexFlow 墨色写死黑色 | **暗色主题下整份乐谱不可见**（1.05:1） | 新增 `--score-ink`，CSS 覆盖 SVG 的 fill/stroke（乐谱是单色印刷品，两主题各自成立） |
| 7 | 零散错误：用边框色当星标色、绿橙强调色当文字 | 局部不可读 | 逐项改语义色 |

## 四、AI 对话能力革新（有特点的方向）

| 改动 | 说明 |
|---|---|
| 工程日志风格 | 消息改为「语义色条 + 等宽元信息」，AI 用青色、用户用 sunset 橙，贴近 IDE 的 diff/日志语言而非通用聊天 App |
| **Markdown 渲染** | 自研零依赖渲染器（`Agent/markdown.tsx`，无 `dangerouslySetInnerHTML`）：标题/列表/引用/代码块/行内粗斜体/表格行。此前模型答复里的 `**粗体**`、`- 列表` 是原样显示的 |
| **对话内提案条** | AI 产出提案时，输入框上方直接出现「N 条提案待审批 + 全部应用」——不必切到右侧面板才知道 AI 做了什么 |
| 实时工具进度 | 等待期显示「正在执行 composer.generateMotif…」而不是三个无信息的点 |
| 会话持久化 | 会话缓存到 sessionStorage：**切标签页、刷新都不再丢失对话**（此前切走即清空） |

## 九、本轮踩到并已修复的一次严重回归（记录在案）

按独立品味建议把走带按钮的 `▶ ■ ❚❚ ● ○ ⟳ ⟲` 批量换成 `<Icon>` 时**漏了 `import { Icon }`** → 渲染期 `Icon is not defined` → React 抛错卸载整棵树 → **整页白屏**，所有截图与用例失效。

- 暴露者：loop-tester（其测试全部变成"页面不存在"）
- 修复：一行 import；`tsc --noEmit` + 首屏冒烟复验通过
- 沉淀：**任何"把字形换成组件引用"的批量改造，收尾必须跑 typecheck + 首屏冒烟**（本仓已有 `typecheck` 脚本，建议挂到 pre-push）
- 同源教训（两个独立核查都中招）：**grep/字符黑名单对 emoji 与特殊字形有假阴性/假阳性**，核验必须走 DOM 文本或结构判据（如"元素内无 `<svg>` 后代"），且新断言要先用"已知失败态"红测一次以自证
