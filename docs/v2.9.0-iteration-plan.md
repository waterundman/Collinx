## 一、审查结论

### 1.1 一句话

v2.8.0 把「推子」从装饰变成了真实接线，但**同一种断线还剩下 6 处**：
界面能改、数据能存、声音不变。本轮就是把这 6 处全部接通，并让导出与播放读同一套混音。

## 二、为什么选这个主题

| 候选 | 用户价值 | 支撑「AI 编曲」主张 | 风险 | 可验证性 | 结论 |
|---|---|---|---|---|---|
| **A 混音闭环** | ★★★★ 最直观（点了就该有反应） | ★★★★ AI 的混音建议第一次能听见 | 中（Web Audio 语义） | 强（电平/频谱/样本可比） | **本轮** |
| B 原生引擎最后一公里 | ★★★ | 中 | 高（Electron+worklet+设备） | 中 | 缓 |
| C 和弦轨发声 + AI 和弦感知 | ★★★★ | ★★★★ | 中 | 强 | v3.0.0 |
| D 自动化曲线 | ★★ | ★ | 低 | 中 | 缓 |

理由：A 是当前**信任成本最低、收益最高**的一刀——「按钮不生效」比「缺功能」更伤。
且它直接修复 AI 主张的漏洞：`mixing.suggestChain` 现在产出的是**听不见的提案**。

## 三、SPEC

**目标**：混音台所有控件（推子/静音/独奏/声像/FX）真实作用于播放与导出；轨道可删；AI 可读混音状态。

**非目标**：VST3/SF2、原生引擎接线、自动化曲线、和弦轨发声、母带 EQ、发送（Sends）真正生效。

**验收标准（可量化，缺一不算过）**

| # | 断言 | 判据 |
|---|---|---|
| A1 | 点 M 后该轨静音 | 该轨总线峰值 < 1e-4，其它轨电平不变 |
| A2 | 独奏只留 solo 轨（多选并集） | 非 solo 轨峰值 < 1e-4；master 不受影响 |
| A3 | 声像等功率 | 全左：R/L 能量比 < 1%；L²+R² = 1 ±0.5dB |
| A4 | FX 真生效 | EQ low −12dB@100Hz → **50Hz 处**能量下降 ≥8dB（100Hz 是转角，物理上是 −6dB）；压缩 ratio 4:1 → 峰值下降且 RMS 上升 |
| A5 | 播放 = 导出 | 同一 `MixerState`，离线渲染与实时链**节点结构签名一致**；mute 轨导出能量 < −80dBFS |
| A6 | 删轨彻底 | 图内该轨 `NoteSpan` = 0、undo 可恢复、混音台少一条、播放无该轨音符 |
| A7 | AI 看得见 | 新只读工具 `mixer.inspect` 返回每轨 gain/pan/mute/solo/effectiveMute/instrument/fx（不改 `project.stats` 既有输出契约） |

## 五、关键技术决策（ADR，开工前定死）

**ADR-1 单一混音图构建器。** `buildMixerGraph(ctx, mixer, dest)` 同时服务 `AudioPreview` 与 `renderNotesToWav`。
不允许在导出侧另写一套连接逻辑——v2.8.0 的「听到的 = 导出的」只覆盖了音色与母带，混音必须同源。
返回 `{ input(trackId), apply(mixer), dispose() }`。

**ADR-2 FX 类型 → Web Audio 映射（6 类全实现）**

| FX | 节点 | 说明 |
|---|---|---|
| eq | 3×BiquadFilter（lowshelf/peaking/highshelf） | 参数就地改（`setTargetAtTime`），不重建 |
| compressor | DynamicsCompressor + makeup Gain | 无 `knee` 之外的自定义，参数直映射 |
| reverb | Convolver + preDelay + wet/dry | **IR 用参数派生的确定性伪随机生成**（同参数同 IR，否则导出 ≠ 播放） |
| delay | DelayNode + feedback Gain + lowpass + wet/dry | 反馈支路加低通，避免高频堆积 |
| saturator | WaveShaper(tanh) + drive/trim | 曲线按 drive 生成，量化为 1024 点后缓存 |
| limiter | DynamicsCompressor(20:1、attack 1ms) + 输出补偿 | Web Audio 无真限幅器，如实注释为近似 |

`enabled: false` = 旁通（wet=0 + dry=1），**不删节点**，避免重建爆音。
仅当**结构签名**（slot id+type 序列）变化时才重建该轨链，重建时旧链 5ms 淡出、新链淡入。

**ADR-3 独奏语义**：`effectiveMute = mute || (anySolo && !solo)`；master 不参与；mute 优先于 solo；
「全部静音」就是静音，不做「全静音时放行」的特殊逻辑。

**ADR-4 bus key 统一**：`resolveBusKey(noteTrackId, mixer)` 优先匹配 `sourceTrackId`，其次 `id`，
未匹配则用原 `trackId` 建总线（0dB）。现状 `App.tsx:976` 用 `sourceTrackId`、音符用 `trackId`，
两套标识靠 demo 巧合对齐；新增轨或配器器出谱后可能错位——这是 S1 的第一件事。

**ADR-5 混音状态本轮不入图。** 入图要动 `DiffEngine` 与 13 类节点，与本轮主题无关；改由
S3/S5 统一从 `MixerState` 快照读取，并在架构书登记为已知债务。

**ADR-6 `core/model/dsp-effects.ts` 与 Web Audio 不追求逐样本等价。**
前者是离线/非浏览器实现，后者是本轮的真实链路。**导出只走 Web Audio 离线渲染**，
不做双实现对齐（对齐成本高、收益为零）。在 `dsp-effects.ts` 顶部注明「非导出路径」。

## 六、验证方案

1. **新基建**：`fake-audio-context.ts` —— 记录节点创建、连接、每个 AudioParam 的写入序列。
   把「接线」变成可断言对象（`master-chain.test.ts:13` 的写法推广）。
2. **纯函数先行**：`mix-resolver.ts` 负责 `effectiveMute / panGains / fxSignature`，先 20+ 条单测（含 NaN/±Infinity 边界）。
3. **断言落在敏感层**：不测"state.mute === true"，测**总线增益为 0**与**导出能量**。
4. **反例矩阵**：solo×mute 共 6 组合；FX 结构变更 × 参数变更 × 旁通；删轨 × undo × 重载。
5. **App 级护栏**：S1–S4 各加一条 App 集成测试——删掉接线必须变红（否则就是零覆盖）。
6. **数值验收**：OfflineAudioContext 渲染 + 手写 DFT 取 100Hz/1kHz 能量；pan 用 L/R 能量比。
7. **独立验证者**：S1–S3 改写的是已验收子系统（播放/导出），按既有规约**必须有独立验证者**做 6-dim；
   若本轮改为单人自证，posterior 不上调并如实标注。

## 七、风险与红线

| 风险 | 对策 |
|---|---|
| jsdom 无 AudioContext → 假绿 | 全部接线断言走 fake ctx；真值由浏览器/离线渲染数值验收 |
| 重建链爆音 | 淡入淡出 + 结构签名判定；播放中不重建 |
| Convolver IR 不确定性 | 参数派生固定种子；同参数缓存复用 |
| pan 用 `StereoPannerNode` 的等功率曲线与手写断言不符 | 以实测曲线为准写容差，不假设公式 |
| 导出时长被 IR 尾巴拉长 | 固定 tail = reverb 预延迟 + IR 长度，写进测试 |
| 删轨误删共享节点 | 只删 `data.trackId === 目标` 的 `NoteSpan`；master 轨禁止删除；兜底保留最后一条 |
| 混音 diff 与本地混音状态互相覆盖 | S5 只读；写仍走既有 `mixerToDiff` |

**红线**：既有测试断言变化必须单独请裁决；禁止为过测缩小输入域；`-Infinity` 语义不得回退成 0。
